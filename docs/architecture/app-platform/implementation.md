# macOS SDK app platform implementation

Goal: all existing apps communicate with Misty through an explicit SDK/RPC contract, install as signed downloadable packages, and export components rendered inside the macOS host without iframes. Windows and mobile follow the working macOS contract.

## Completion gates

1. Inventory all ten official apps and the six catalog extensions, including transitive native calls, server requests, events, streams, uploads, local caches, and lifecycle cleanup. Classify dynamic requests rather than treating them as covered.
2. Define the versioned SDK method registry with typed parameters/results, declared capabilities, platform support, cancellation, errors, and resource ownership. Unknown methods must fail. Credential access and host administration must not become app methods merely because they appear in old imports.
3. Implement native host adapters and server RPC dispatch with shared contracts. Test both successful operations and denied/expired/cross-account requests. Live event subscriptions and binary/streaming operations need explicit contracts.
4. Migrate app dependencies to SDK adapters. Build checks must reject direct native imports, raw host credentials, and direct server transports in downloadable packages. Sharing React is allowed; sharing authenticated host stores is not a substitute for SDK methods.
5. Restore signed catalog artifacts and package installation. Verify exports before mounting, preserve independent tab/Space lifecycles, and connect navbar/tab/panel integration through SDK workspace methods.
6. Verify macOS launch and actual install/open/interact/close/reopen/uninstall flows. Do not mark the goal complete based only on builds or source-contract tests.

## Working architecture

A downloaded component receives an SDK instance bound to its app, account, Space, tab, permissions, and lifetime. SDK methods dispatch to host-owned native services or the authenticated server RPC endpoint. Packages never receive account tokens or unrestricted native invoke. The host owns window creation, authentication, resource grants, and teardown. Application screens and app-local state live in the downloaded bundle.

Signed first-party components sharing the host document are trusted code; an SDK contract alone is not a JavaScript security sandbox. Untrusted extensions retain the existing separate native WebView runtime while using the same SDK method contracts. Neither runtime requires an iframe.
